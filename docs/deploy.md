# Выкладка

Пилот — одна машина Yandex Cloud (PRD, раздел 11): приложение, PostgreSQL и Caddy с HTTPS в
Docker Compose. Образ собирается на компьютере разработчика и уезжает на сервер готовым.

Проверено на компьютере: сборка, запуск собранного сервера, миграции при старте. Docker-образ,
Caddy и резервные копии ещё не запускались — нет сервера и Docker на компьютере.

## Один раз: сервер

1. Владелец создаёт аккаунт Yandex Cloud и машину: 2 vCPU с долей 20%, 2 ГБ, SSD 20 ГБ,
   статический IP, Ubuntu, доступ по SSH (PRD, раздел 15).
2. На сервере — Docker: `curl -fsSL https://get.docker.com | sh`.
3. В DNS домена — запись A на статический IP.
4. На сервере `/opt/knizhki/.env` по образцу `deploy/.env.example`. Пароль базы и ключ
   `NEXT_SERVER_ACTIONS_ENCRYPTION_KEY` — `openssl rand -base64 32`.
5. В Яндекс ID и VK ID адреса возврата: `https://ДОМЕН/auth/yandex/callback` и
   `https://ДОМЕН/auth/vk/callback`. Доступы: почта и имя.

## Каждая выкладка

На компьютере разработчика с Docker: `./deploy/deploy.sh ubuntu@IP`. Скрипт прогоняет линтер и
тесты, собирает образ под `linux/amd64`, копирует его и конфигурацию, перезапускает сервисы.
Миграции применяются при старте приложения.

## Резервные копии

1. Бакет в Yandex Object Storage (1 ГБ бесплатно), сервисный аккаунт с ролью
   `storage.uploader` и статический ключ — в `.env` (`BACKUP_BUCKET`, `AWS_ACCESS_KEY_ID`,
   `AWS_SECRET_ACCESS_KEY`).
2. Правило жизненного цикла бакета: удалять объекты старше 14 дней.
3. На сервере `crontab -e`: `30 3 * * * cd /opt/knizhki && ./backup.sh >> backup.log 2>&1`.
4. Проверка восстановления (обязательна в фазе 1): `./restore.sh МЕТКА` на копии и вход на сайт.

## Удалить всё

Если гейт A не пройден: удалить машину, диск, статический IP и бакет — они оплачиваются
даже у выключенной машины (PRD, раздел 11).
